# SPEC-001：构建基线与鸿蒙适配可行性

状态：草案。阶段：M0。关联：REQ-001、REQ-002、REQ-009。更新：2026-09-30。

上位规格：[产品需求与架构 v0.3](../SPEC.md)。本阶段只在受控环境验证；M1 公网安全门槛通过前不把验证构建作为公网可用产品发布。

## 目标

回答两个问题：当前官方基线能否在本机重现 Windows 构建；哪些官方客户端模块可复用于鸿蒙原生控制端，以及最先需要适配的依赖和平台边界是什么。

用户已确认鸿蒙 6.1 真机和开发环境均已有。本阶段先核验这些现有条件，允许小范围的可丢弃验证工程；在确认许可路线后再引入实现代码。不是在此阶段建立整套多协议 SDK。

## 范围

- 记录构建与设备环境，固定 RustDesk 及子模块提交。
- 按官方构建要求重现 Windows 应用，使用可控对端验证基本连接、画面与输入。
- 根据 `Cargo.toml`、`src/lib.rs`、客户端会话/界面接口梳理跨编译依赖和 Android/iOS 条件之外的桌面依赖。
- 验证鸿蒙 ARM64 的最小 NAPI/C ABI → Rust 调用，明确编译、签名、安装和事件回调方式。
- 对官方连接能力做可复用性检查：配置、认证、取消、错误事件、直连/中继选择；列出所需平台挂钩，不在本阶段承诺网络打洞成功。
- 单独检查无 hbbs/hbbr 的 IP 直连：地址与端口解析、被控监听、目标身份验证、加密和授权接入；不能将已有 secure=false 入口直接判作安全模式已完成。
- 记录鸿蒙原生视频解码与渲染边界的最小验证方案，供 M1 实施；编译成功不能替代真机画面证据。

## 不在本阶段实施

不修改密码学、权限语义、视频协议，不做品牌替换、多协议接入、窗口串流或省流重写；不因适配鸿蒙大范围改造现有桌面与移动路径。

## 验收清单

- [ ] 记录目标鸿蒙真机型号、系统/API，以及 Windows 构建环境版本。
- [ ] 记录基线、子模块 SHA、构建命令和成功/失败输出摘要。
- [ ] Windows 原版可启动并建立基本远控连接，记录连接路径和对端版本。
- [ ] 最小鸿蒙 native 调用在目标真机成功，至少验证一次异步结果回传与退出清理。
- [ ] 输出官方核心依赖清单：可直接复用、需平台适配、当前阻塞三类，每项附文件与原因。
- [ ] 明确 M1 的最小会话接口和媒体交接方式，不假定官方现有 crate 是独立跨平台 SDK。
- [ ] 对仍不成立的条件记录限制，SPEC 与 PROGRESS 状态一致。

## 实现前决策

目标设备已确定为用户现有的鸿蒙 6.1 真机，具体型号和 API 随环境盘点补记。控制端许可方向仍需明确；此时可先做工具链盘点和只读依赖分析。第三方源码仅按适用许可证使用，不因「参考」而绕过来源与许可记录。

M0 完成后根据验证结果确认 M1 的实现规格，再进入逐文件任务拆分。
