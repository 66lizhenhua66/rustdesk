# SPEC-005：触屏展示与手势控制

日期：2026-10-08。状态：共享核心与鸿蒙接线已实现，Flutter 接线待后续。

本规格细化 [SPEC-004](004-cross-platform-input.md)，解决手机与远程 Windows 分辨率不同、自动旋转、安全区域、画布缩放和触屏手势之间的关系。

## 1. 目标

- 竖屏和横屏都完整显示远程画面，默认保持远程宽高比。
- 顶部状态栏、底部手势区、刘海、圆角和会话工具栏不遮挡可操作的远程内容。
- 捏合缩放范围为 `1.0x` 到 `10.0x`，缩放只影响本地展示和坐标换算，不改变远程分辨率、编码或网络流量。
- 手机旋转后保留当前缩放比例和画布中心，重新计算安全区域和画布边界。
- 缩放后显示浮动“还原画面”按钮，一次恢复 `1.0x` 和居中位置。
- 触屏模式中，单指点击、长按拖动、双指右键、双指滚轮和捏合缩放互不误触。

## 2. 展示模型

### 2.1 安全画布

先从窗口计算 `SafeRect`：扣除系统安全区、会话工具栏、底部状态条和必要的交互间距。远程画面只在 `SafeRect` 中布局；额外黑边属于本地画布背景，不属于远程坐标，也不能产生点击。

```text
safeRect = windowRect - systemInsets - sessionOverlays
fitScale = min(safeRect.width / remote.width,
               safeRect.height / remote.height)
actualScale = fitScale * zoomFactor
```

`zoomFactor` 的范围是 `[1.0, 10.0]`。`1.0x` 表示完整适应窗口，画面居中；大于 `1.0x` 时，远程画面可以超过安全画布并通过 `panOffset` 移动。画布边界限制保证远程内容可以移动到安全区域内，黑边不会被误认为远程画面。

### 2.2 坐标变换

远程点到本地画面：

```text
localX = imageOffsetX + panX + remoteX * actualScale
localY = imageOffsetY + panY + remoteY * actualScale
```

本地点到远程坐标：

```text
remoteX = (localX - imageOffsetX - panX) / actualScale
remoteY = (localY - imageOffsetY - panY) / actualScale
```

逆变换结果超出远程画面范围时，事件只作用于本地画布或黑边，不发送远程输入。所有点击、拖动和鼠标移动都使用这份变换，避免展示位置与 Windows 光标位置不一致。

### 2.3 旋转

窗口尺寸或系统安全区变化时：

1. 取消当前触摸、捏合和长按计时，释放远程按键/按钮。
2. 用旧变换把当前视口中心转换为远程坐标 `remoteCenter`。
3. 重新计算 `SafeRect`、`fitScale` 和 `actualScale`。
4. 让 `remoteCenter` 继续落在新的安全画布中心。
5. 按新的画布边界限制 `panOffset`。

如果旧中心在新的边界下无法保持，使用最近的合法偏移；不静默改变远程控制模式，不断开会话。

## 3. 触屏手势

### 3.1 单指

- 单指按下后进入等待状态，不立即发送点击。
- 抬手时移动距离小于阈值且未进入拖动，发送远程左键单击。
- 按下后在 `1s` 内移动：当 `zoomFactor > 1.0` 时平移本地画布；`1.0x` 时保持画面居中，不把普通滑动误判成远程拖动。
- 按下保持 `1s` 且没有明显移动时，进入“拖动准备”状态，显示提示；此时不发送远程左键按下。
- 进入拖动准备后再次移动，先发送当前位置，再发送左键按下，之后的移动拖动远程对象。
- 拖动抬手发送左键释放；长按后没有移动直接抬手时不发送点击。

长按不再承担右键语义，右键由双指点击触发，避免长按与远程拖动互相冲突。

### 3.2 双指

- 两指快速按下并抬起，距离和中心移动都在阈值内：远程右键单击。
- 两指距离发生变化：进入捏合缩放，更新 `zoomFactor`，不发送远程鼠标事件。
- 两指距离稳定、中心上下移动：发送远程滚轮。
- 捏合后的单指移动：平移画布。

捏合和滚轮的判定以距离变化优先；一旦进入捏合，本次双指序列不再产生右键或滚轮。

### 3.3 浮动按钮

当 `zoomFactor > 1.0` 时，在 `SafeRect` 内显示“还原画面”按钮。点击按钮：

```text
取消当前手势
zoomFactor = 1.0
panOffset = 居中位置
remoteCenter = 远程画面中心
```

按钮只改变本地展示，不断开会话、不关闭键鼠授权、不清理远程输入队列。还原后隐藏按钮。

## 4. 跨平台边界

共享 Rust 交互引擎保存 `zoomFactor`、`panOffset`、触点状态和手势状态，并提供安全区域、变换和长按状态的纯数据接口。鸿蒙、Android、iOS 和 Windows 控制端各自提供窗口尺寸、安全区、系统输入法和浮动按钮；不复制手势判定。当前鸿蒙接线使用固定交互 padding，系统 insets 仍以 0 传入，待真机 API 接线后替换为真实状态栏/手势区数据。

平台适配必须向共享引擎提供：

- 远程画面尺寸；
- 本地窗口尺寸和系统安全区；
- 当前显示变换；
- 触点集合及时间戳。

Windows 被控端不参与本地画面缩放，只接收归一化后的鼠标命令。远程编码、画面分辨率和网络流量保持不变。

## 5. 验收场景

- 1920×1080 远程画面在竖屏和横屏中完整居中，黑边不能点击。
- 竖屏放大到 `10.0x` 后，文字区域可通过单指平移查看，远程点击坐标准确。
- 放大后旋转屏幕，缩放比例和远程画面中心保留，偏移不越界。
- 点击“还原画面”后恢复 `1.0x` 居中，按钮消失，连接和控制模式保持不变。
- 单指轻点、`1s` 长按拖动、双指右键、双指滚轮和捏合缩放不会互相触发。
- 旋转、失焦、后台、触摸取消和断开都释放按下状态。
- 普通输入、系统输入法和 Alt+Tab 的平台限制继续按 [键盘核查](../research/2026-10-07-harmony-keyboard-routing.md) 验收。
