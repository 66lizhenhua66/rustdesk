# SPEC-005：触屏展示与手势控制

日期：2026-10-08。状态：用户确认的整屏画布与侧边浮球已实施、构建并安装，部分真机显示验证通过，完整体验继续验收。见 [实施计划](../plans/2026-10-08-fullscreen-orb.md)；取代显示区域裁成 SafeRect 的早期布局。

本规格细化 [SPEC-004](004-cross-platform-input.md)，解决手机与远程 Windows 分辨率不同、自动旋转、安全区域、画布缩放和触屏手势之间的关系。

## 1. 目标

- 竖屏和横屏都完整显示远程画面，默认保持远程宽高比。
- 系统安全区保护输入与悬浮控件，显示可以延伸至边缘；浮层挡住的远端内容可通过平移移入可操作区域。
- 捏合缩放范围为 `1.0x` 到 `10.0x`，缩放只影响本地展示和坐标换算，不改变远程分辨率、编码或网络流量。
- 手机旋转后保留当前缩放比例和画布中心，重新计算安全区域和画布边界。
- 缩放后显示浮动“还原画面”按钮，一次恢复 `1.0x` 和居中位置。
- 触屏模式中，单指点击、长按拖动、双指右键、双指滚轮和捏合缩放互不误触。

## 2. 展示模型

### 2.1 整屏画布与安全输入区域

`Viewport` 是整屏画布，显示时使用完整窗口。浮球、工具面板、还原按钮和系统键盘覆盖画面，不为它们留出固定条带。单独计算 `SafeRect`，仅用于远端输入命中与悬浮控件避让系统区域；不再用它缩小画面。

```text
viewport = fullWindowRect
safeRect = viewport - systemInsets
fitScale = min(viewport.width / remote.width,
               viewport.height / remote.height)
actualScale = fitScale * zoomFactor
```

`zoomFactor` 的范围是 `[1.0, 10.0]`。`1.0x` 表示完整适应整个屏幕并居中，不表示远端像素与本地像素 1:1。16:9 远端在约 2.15:1 手机横屏中会有左右自然黑边；这是保持完整比例的结果。约 1.2× 可以填满宽度，此时远端上下部分超出屏幕，需要平移查看。

大于 `1.0x` 时可以单指平移，并允许越过边界约 24 vp 的额外余量，把远端边缘移入安全操作区域。黑边属于本地画布，触屏 direct 模式不把图像外点击发送到远端；指针模式保留触摸板语义。菜单展开和关闭不能改变 fit、缩放或画布中心。

### 2.2 坐标变换

远程点到本地画面：

```text
localX = imageOffsetX + panX + remoteX * actualScale
localY = imageOffsetY + panY + remoteY * actualScale
```

本地点到远程坐标：

```text
remoteX = (localX - imageOffsetX - panX) / actualScale
remoteY = (localY - imageOffsetY - panY) / actualScale
```

逆变换结果超出远程画面范围时，事件只作用于本地画布或黑边，不发送远程输入。所有点击、拖动和鼠标移动都使用这份变换，避免展示位置与 Windows 光标位置不一致。

### 2.3 旋转

窗口尺寸或系统安全区变化时：

1. 取消当前触摸、捏合和长按计时，释放远程按键/按钮。
2. 用旧变换把整个视口中心转换为远程坐标 `remoteCenter`。
3. 根据新的完整视口计算 `fitScale` 和 `actualScale`，另行更新输入 `SafeRect`。
4. 让 `remoteCenter` 继续落在新的视口中心。
5. 按新的画布边界限制 `panOffset`。

如果旧中心在新的边界下无法保持，使用最近的合法偏移；不静默改变远程控制模式，不断开会话。

## 3. 触屏手势

### 3.1 单指

- 单指按下后进入等待状态，不立即发送点击。
- 抬手时移动距离小于阈值且未进入拖动，发送远程左键单击。
- 按下后在 `1s` 内移动：当 `zoomFactor > 1.0` 时平移本地画布；`1.0x` 时保持画面居中，不把普通滑动误判成远程拖动。
- 按下保持 `1s` 且没有明显移动时，进入“拖动准备”状态，显示提示；此时不发送远程左键按下。
- 进入拖动准备后再次移动，先发送当前位置，再发送左键按下，之后的移动拖动远程对象。
- 拖动抬手发送左键释放；长按后没有移动直接抬手时不发送点击。

长按不再承担右键语义，右键由双指点击触发，避免长按与远程拖动互相冲突。

### 3.2 双指

- 两指快速按下并抬起，距离和中心移动都在阈值内：远程右键单击。
- 两指距离发生变化：进入捏合缩放，更新 `zoomFactor`，不发送远程鼠标事件。
- 两指距离稳定、中心上下移动：发送远程滚轮。
- 捏合后的单指移动：平移画布。

捏合和滚轮的判定以距离变化优先；一旦进入捏合，本次双指序列不再产生右键或滚轮。

### 3.3 侧边浮球与还原

右侧 44 vp 浮球可以沿安全区域上下移动。点击向屏幕内侧展开紧凑工具面板，提供控制/仅查看、键盘、触屏/指针、还原、断开与返回设备。浮球拖动和菜单点击不进入远端输入；点击菜单外关闭时消费该次操作，避免点穿远端。已批准的手势和前台常亮继续保留。

当 `zoomFactor > 1.0` 时，在安全区域左上方显示包含当前倍数的“还原”按钮。它浮在整屏画布上，不占据固定布局高度。点击按钮：

```text
取消当前手势
zoomFactor = 1.0
panOffset = 居中位置
remoteCenter = 远程画面中心，映射至完整视口中心
```

按钮恢复本地展示，不断开会话或关闭键鼠授权。如有远端按钮按住，先释放并取消当前手势，避免卡键；还原后隐藏按钮。

### 3.4 指针模式

会话工具提供「触屏模式 / 指针模式」选择，与「控制 / 仅查看」独立。指针模式单指滑动发送相对移动，不把光标跳到手指位置；轻点左键、双指轻点右键、双指移动滚轮、长按 1 秒后拖动。捏合仍缩放本地画布；仅查看时只允许本地平移/缩放，不输出远程命令。切换触控模式取消当前手势并释放按下状态。

2026-10-09 修正：这里的「相对移动」指触摸板交互，网络命令统一发送累积后的绝对目标，避免把视频像素差误当作 Windows 的归一化相对量。进入指针模式或随后获得控制许可时，将真实鼠标定位到可见远端区域中心，下一视频帧呈现真实光标；不叠加第二个本地预测箭头。普通 configure 不重置指针。

### 3.5 独立键盘与停靠占用

右侧工具浮球旁常驻独立键盘悬浮按钮，打开和收起不需进入菜单。按钮位置按可用区域限位，未获输入许可时禁用。键盘打开状态与平台报告的停靠占用分别处理。

鸿蒙 `TYPE_KEYBOARD` 表示固定态软键盘区域。该区域与完整窗口相交时，视频/输入视口采用键盘上方剩余高度，并保持当前缩放及关注位置；浮窗键盘没有固定态占用，不缩小整个画布，也不把「无占用」误判成键盘关闭。系统状态栏、导航条与键盘不重复扣减。未来平台只需适配实际停靠占用矩形。

### 3.6 分辨率、压缩清晰度与帧率

普通已批准会话在浮球菜单「画质 / FPS」中使用 v2 设置，分辨率策略、压缩清晰度和 FPS 独立选择。默认保持 Windows 桌面，以 1080p 为传输上限，使用均衡压缩清晰度和 15 FPS。`low` / `balanced` / `high` 对应省流、均衡、清晰，只调整压缩清晰度；FPS 提供 10 / 15 / 30 目标上限。

- **保持 Windows 桌面（`preserve`）**：不修改 Windows 实际显示模式，只缩放采集后发送的画面。可选择跟随源画面（宽高均为 `0`），或 720p / 1080p / 1440p 传输上限；保持源宽高比且不放大小屏。跟随源画面也受单轴 4096、总像素 8,294,400 的编码上限约束，超限时等比缩小，并将编码尺寸取为偶数。
- **同步调整 Windows 桌面（`sync`）**：只列出主屏驱动支持且与当前刷新率、方向等属性兼容的尺寸；指定尺寸须为偶数、单轴不超过 4096、总像素不超过 8,294,400。临时改变 Windows 桌面后再采集编码，不修改 DPI、刷新率等属性，不写持久显示设置。宽高均为 `0` 表示恢复本次连接前的原始模式。同步需要本次普通连接已批准、输入已授权且本机输入能力门禁仍开启；未获得支持列表或同步能力时不能任意请求尺寸。

每次连接初始都使用 `preserve`，不自动应用上一次的同步选择；本地偏好只保存保持策略的默认分辨率及压缩清晰度、FPS。从 `sync` 切回 `preserve` 时先恢复本次连接前的原始显示模式。同步前界面提示本机可能闪屏或窗口重排。

选择参数后必须点击「应用设置」。客户端清除待发输入并先释放按下状态，被控端撤销旧输入令牌、停止旧采集并等待线程退出；需要切屏时验证并应用临时 Win32 显示模式，再重建采集与编码器。首关键帧准备好后，原先已启用的输入获得新令牌，随后发送匹配请求的实际状态确认及首帧。等待期间禁止重复设置和新输入，但仍可关闭输入；v2 初始及运行期确认窗口均为 20 秒。界面只按确认显示实际 Windows 尺寸、传输尺寸、本次连接前尺寸和已应用选项。

可恢复的切换或视频重建失败返回错误原因及上一实际配置，回退后继续视频；回退失败则结束会话并保留恢复记录。正常断开或退出尽力恢复原始模式。异常退出留下的恢复日志在下次显式启动被控服务时检查恢复，没有独立 watchdog，不保证崩溃瞬间恢复；检测到外部显示设置或拓扑变化时不覆盖本机后续改动。

实际帧率取决于画面变化、网络与软件编解码性能，静止帧继续跳过，不承诺无损、固定 30 FPS 或 4K 实时性能。v1 设置仍保留画质绑定分辨率上限的既有行为；未协商视频设置的旧诊断与可信只读访问保留 720p / 8 FPS。实施范围见 [桌面分辨率计划](../plans/2026-10-09-desktop-resolution.md)，真实切屏、回退与恢复仍需设备验收。

## 4. 跨平台边界

共享 Rust `canvas.rs` 保存缩放、画布位置、触点和手势状态，`canvas.h` 提供版本化 C ABI。鸿蒙、Android、iOS 和 Windows 控制端各自提供窗口尺寸、安全区、系统输入法和浮动按钮；不复制手势判定。

鸿蒙读取窗口的 SYSTEM、CUTOUT、NAVIGATION_INDICATOR 与 KEYBOARD 避让矩形，转换为 vp 后与实际完整视口求交。会话页使用真正扩展的整窗布局，工作台保持常规布局；系统键盘以 NONE 模式覆盖，由应用按照真实固定态占用单独计算有效视口，其余系统区域仅约束输入与浮层，避免重复扣减。浮窗键盘不缩视口，隐藏会话时恢复原键盘避让模式。

鸿蒙 configure 使用 `fullViewport=true`、`padding=0`；画面基础尺寸保持完整 viewport 的 fit 大小，由绘制缩放呈现 1～10 倍，按完整 viewport 裁剪；输入绑定未缩放的整个视口，使用 Rust 快照的 imageX/Y 绝对坐标，不再扣 safeX/Y。错误和长按拖动提示仍为短暂悬浮层。`fullViewport` 缺省为 false，保留其他现有调用的安全画布行为。

Flutter 提供 `ControllerCanvasEngine`、`FlutterCanvasInputAdapter`、`ControllerCanvasView`，共用同一 ABI，读取 MediaQuery 安全区并叠加应用工具栏区域。组件要求父布局随软键盘收缩（例如 Scaffold 默认 `resizeToAvoidBottomInset: true`）；保留覆盖式键盘的页面须先按键盘可见区域约束画布。该可复用组件尚未接入完整 Windows/Android/iOS 生产控制端页面，原生库打包、签名与设备测试是相应平台后续交付。

`configure` 控制本地画布输入许可，不能替代会话授权。失败时停止后续命令；`suspend` 清本地按下和手势状态并禁用输入，保留视图缩放，远端撤权仍由既有会话 API 完成。仅查看会话也能查看、缩放、平移和还原。

平台适配必须向共享引擎提供：

- 远程画面尺寸；
- 本地窗口尺寸和系统安全区；
- 系统和应用实际占用的安全区域；
- 触点集合及时间戳。

Windows 被控端不参与本地画面缩放，只接收归一化后的鼠标命令。远程编码、画面分辨率和网络流量保持不变。

## 5. 验收场景

- 1920×1080 远程画面在竖屏和横屏中完整居中，黑边不能点击。
- 竖屏放大到 `10.0x` 后，文字区域可通过单指平移查看，远程点击坐标准确。
- 放大后旋转屏幕，缩放比例和远程画面中心保留，偏移不越界。
- 点击“还原画面”后恢复 `1.0x` 居中，按钮消失，连接和控制模式保持不变。
- 单指轻点、`1s` 长按拖动、双指右键、双指滚轮和捏合缩放不会互相触发。
- 旋转、失焦、后台、触摸取消和断开都释放按下状态。
- 普通输入、系统输入法和 Alt+Tab 的平台限制继续按 [键盘核查](../research/2026-10-07-harmony-keyboard-routing.md) 验收。
