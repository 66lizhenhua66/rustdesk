# 鸿蒙真机待验清单

日期：2026-10-04。代码基线：`be1601ca7`；已有现场证据记录于 `3c6984b70`。状态：**全部真机项目待验证**。用户要求真机验证后移，不阻塞当前实现；每次新增或修改平台能力时，在本清单补充对应待验项。

本清单对应 [SPEC-002](../specs/002-controller-tech-stack.md) 和 [当前进度](../PROGRESS.md)。模拟器、Windows 本机、自动化测试、ARM64 编译及 2in1 模拟器布局结果分别记录，不能代替 HarmonyOS 6.1 手机或平板真机结果。

## 已有证据与测试前提

- [控制端能力验证](../research/2026-10-04-controller-capability-validation.md) 已记录手机 API22 模拟器经一次 Windows 本机批准后开启控制、确认文本 `REMOTE-中文-2` 到达专用记事本，以及切回仅查看并保持视频。完整拼音候选输入、鼠标、滚轮、物理按键和按住状态释放未据此通过验收。
- 当前正式路径为 ArkUI → NAPI/C ABI → Rust 共享会话核心；视频为 VP8 软件解码 → NativeWindow/Surface。首轮真机测量以当前软件路径为基线。
- 记录真机型号、系统完整版本、实际 API level、ABI、屏幕尺寸与显示缩放。手机和平板分别填写；缺少平板时保留平板待验，不能用拉宽窗口替代。
- 使用有效的本地调试签名安装 HAP，记录提交 SHA、HAP/Windows 整包版本及哈希。保护 `apps/harmony-controller/build-profile.json5`，不提交签名资料、凭据或设备唯一标识。
- Windows 使用正式 Flutter 工作台和受控测试配置。保持默认关闭的 `-Video -Input` 能力门禁；每次接入仍由用户在 Windows 本机批准一次，接入后由控制端切换键鼠。
- 实际局域网测试需预先明确目标地址、端口与允许来源，保持身份验证和加密；不自动扩大公网监听或修改防火墙。HDC 转发结果单独标记，不能算无线局域网直连通过。
- 输入只在专用测试窗口/文件中验证，先确认前台焦点；不得操作用户其他文档。异常时由 Windows 本机用户结束连接。

当前视频上限为 1280×720、约 8 fps，相同像素不重复发送；静止时低帧率不直接判为故障。帧计数与提交次数不能当作端到端延迟指标。

Windows 锁屏/UAC/安全桌面边界也须补充现场验证：只检查当前会话能安全停止或拒绝输入，不要求控制安全桌面或提权。该项属于 Windows 执行边界，使用模拟器即可先做，真机联调时再回归。

## 后续实现后再增加真机验收

以下能力尚未接通或没有完整实现，不应写成“只差真机测试”：

- 系统声音、跨端剪贴板、文件传输：先实现独立能力协商、控制端开关与断开清理，再验收实际设备播放/焦点、数据边界和撤销。
- 直接触控定位、双指缩放/滚动、物理滚轮、完整快捷键/外接输入体验和即时输入法：按各切片实现范围补充映射、缩放、候选文本与焦点验收。
- 硬件解码、动态画质、多屏和窗口范围：先实现与协商，再按设备实际能力测试；当前 VP8 软件路径不能作为硬解证据。
- ID/自建中继、完整官方会话接入、可信控制设备绑定、2FA 继续流程及无人值守：先完成对应协议与安全切片。局域网通过不等于跨网或公网通过。
- Android/iOS 共享核心接入另建各平台真机清单；鸿蒙通过不替代第二平台验证。
- 敏感凭据安全存储适配：实现后单独检查凭据保存、读取和失效；现有非敏感设备资料持久化不作为安全存储通过的证据。
