# 控制端能力开关流程调整

日期：2026-10-04。基线 `499b89441`。用户明确改为：被控端只批准或拒绝接入，控制端决定键鼠、声音等能力是否开启。此决定替代上一切片的第二次 Windows 键鼠授权；已有严格身份、加密、逐连接接入批准、被控端终止与执行点清理继续保留。

## 确定的流程

1. 手机连接后等待 Windows 本机一次批准。Windows 提示接入后可使用本机已开放的能力；只有批准后才可查看和请求操作。
2. 手机默认保留当前“仅查看”选择；点“控制”即请求开启键鼠，不再让用户回 Windows 点击“允许键鼠”。界面等待真实状态回执，成功才进入可发送输入的面板。
3. 手机切回“仅查看”、关闭输入面板或隐藏会话时请求关闭键鼠，立即停止本地发送并清队列；Windows 释放按键/按钮、使令牌失效并回执。再次开启得到新令牌。
4. Windows 展示键鼠当前开关状态，保留“结束本次连接”，移除独立允许/撤销键鼠按钮。连接结束收回所有本次能力。
5. 声音、文件、剪贴板仍未实现，保持禁用并明确标注，不模拟开启。开发入口 `-Input` 和原本机能力上限仍是默认关闭的实现门禁，不能由远端越过；本次测试服务已显式配置该能力。

## 最小协议与状态改动

- 新增 Message 字段 36 `OrdInputRequest { version, enabled, scope, request_id }`。scope 固定 `windows_primary`，合法消息自然长于旧的 16 字节短明文保护界限；不移除旧安全检查。
- `LoginRequest.ord_input_version` / PeerInfo `input_version` 升为 2，明确此版允许控制端在接入获准后开关能力；旧 `secure_video` 不变，旧输入代际不静默改语义。
- OrdInputState 新增 `request_id`，请求回执原样回显；0 保留给初始支持状态/服务主动关闭。核心为请求分配递增 ID，忽略过期请求回执，避免快速开关后迟到授权反向启用输入。授权令牌仍不交给界面。
- 核心新增 `controller_session_set_input_enabled_v1`。关闭在同一状态锁内清令牌及输入队列，并优先发送关闭请求；快速关闭→开启按顺序撤权再申请新令牌。请求队列有界；无法排入关闭请求则终止会话，不能漏掉释放。
- Windows 仅在已批准、输入 v2 协商、本机能力上限允许时处理请求。开启复用现有执行适配，关闭复用撤权/释放；关闭不受流量预算阻挡。第二次键鼠授予不再检查本机点击时间；最初接入批准继续强制检查。
- 原 CM 键鼠切换命令不再驱动新协议授权，只同步状态。令牌、单输入拥有者、桌面边界、双向心跳与明确释放失败继续使用。

## 实施顺序与验收

- [x] core/proto/C ABI：开关请求、回执相关性与有界优先关闭；覆盖未批准/旧模式拒绝、迟到回执、快速开关、新令牌及现有只读回归。
- [x] Windows：输入请求分类/执行、能力上限与现有预算；保留接入批准门禁，取消第二次 CM 输入授予。
- [x] Flutter：删除允许/撤销输入操作，改为只读状态和一次接入许可说明；原接入批准、拒绝、终止不变。
- [x] Harmony：控制按钮以“已接入+支持+有画面”决定可点击，调用开启接口并等待实际 input_state；本地停止发送不冒充服务已关闭。视频统计事件不能误清待开启意图。
- [x] 必要回归、Windows/HAP 构建与安装；本机用户只点一次接入批准后，在专用记事本验证控制端开启、输入、关闭。鼠标/滚轮/物理按键尚待单独现场补测；记录、本地提交、不推送、刷新索引已完成。

原型和本地签名/工具配置保持不变。该调整改变能力决定位置，不放宽未经接入批准的执行权限，也不实现音频等后续能力。
