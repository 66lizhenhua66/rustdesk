# 触屏与键鼠输入解耦

用户要求：将输入适配从会话 UI 解耦，为后续触屏、键鼠操作体验迭代提供独立改动和测试位置。延续已确认的默认控制／可选仅查看交互。

## 设计

采用会话输入控制器与两类独立输入适配器。直接把所有方法搬进单个大类仍会让触屏和键鼠相互牵连；通用插件注册或跨平台框架目前没有第二个平台调用者，不纳入本轮。

- `input/InputEvents.ts`：平台无关事件值与适配器使用的最小命令出口。
- `input/TouchInput.ts`：点按、长按、拖动、双指滚动和触摸状态。
- `input/MouseKeyboardInput.ts`：鼠标按钮/滚轮、物理按键和修饰键状态。
- `input/SessionInputController.ts`：控制模式、只读门禁、输入回执、统一发送/失败处理、坐标与释放生命周期，向页面提供状态快照。
- `input/HarmonyInputAdapter.ets`：把 ArkUI 事件和 KeyCode 转成上述值类型，处理平台事件传播；不做手势判定或授权决策。
- `service/RemoteInputMethod.ets`：继续独立管理系统 IME 绑定，命令送进同一输入控制器。
- `components/RemoteSession.ets`：显示画面/工具栏、绑定事件与焦点、将会话和画面尺寸通知控制器。

输入逻辑不依赖 ArkUI、NAPI、JSON 或页面实例。发送、能力开关、释放、系统键盘和焦点通过构造时的依赖传入。只维护一份控制/按下状态，页面收到的状态对象只用于渲染。Rust 协议和 Windows 输入执行器不因本轮解耦修改。
