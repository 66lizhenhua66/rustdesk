# 键盘、指针与画质/FPS 改进

日期：2026-10-09。基线：`8d025efbc`。用户要求键盘独立悬浮、停靠键盘占用适配、正确触摸板指针，以及多档画质和 FPS。沿用当前已批准的整屏画布与侧边浮球。

## 行为与边界

1. 键盘按钮与工具浮球组成右侧悬浮组。键盘状态与键盘占用独立；鸿蒙 `TYPE_KEYBOARD` 只代表固定态软键盘区域。停靠键盘出现时使用上方剩余视口，浮窗键盘无固定占用，不据 `keyboardOpen` 缩图。未来平台只需提供同类占用矩形。
2. 指针模式首次选中或之后获准控制时，将真实鼠标移到可见远端区域中心。手指 delta 只更新共享光标目标；移动、点击、滚轮与拖动都发相同坐标系的绝对命令，修正视频像素差被误当归一化相对量的问题。显示视频内真实系统光标，避免叠加第二个预测箭头；出现需要下一视频帧。
3. 普通会话默认标准 1080p / 15 FPS，支持省流 720p、标准 1080p、高清 1440p及独立 10/15/30 FPS目标上限。按会话内即时切换实现，实际选择须等被控端确认，等待期间禁止重复请求。分辨率是上限，保持源屏幕比例，不放大小屏。
4. 新视频能力显式协商；旧请求、旧诊断和可信只读访问保留原 720p/8FPS。仅已经批准的普通 control 视频会话可重配，不要求输入许可，也不能因此获得输入权限。

## 协议顺序

初始登录的 `ord_video_settings` 为 version=1、request_id=1，服务端仅为此请求增加 `video_settings_version=1` 能力元数据。LoginResponse后先发 OrdVideoState，随后首关键帧。运行时 request_id 从2递增，始终最多一个等待确认请求。质量仅 low/balanced/high，FPS仅10/15/30；未知字段、错误确认或超界尺寸拒绝，超时明确失败。

host 单写入循环保证旧帧全部在 ACK 前；切换后旧 receiver 已销毁，不能继续发送旧尺寸帧。ACK 后客户端更新解码尺寸，并要求新关键帧。新消息最短序列化正文必须大于16字节，以兼容严格入口既有短明文拒绝策略，不削弱加密校验。

## 回归与产物

输入共享核心、Windows专属视频与鸿蒙媒体桥需要配套更新。本次新增软件编解码档位不承诺1440p/30FPS实测性能，不提供未经验证的4K或“原画无损”选项。高帧率只是采集目标，静止画面仍不重复编码。

代码、自动化与双端构建已完成，Windows 已更新并恢复原受限测试入口；手机无线调试端口拒绝连接，安装等待可用地址。证据和待验范围见 [验证记录](../research/2026-10-09-input-and-video-validation.md)。
