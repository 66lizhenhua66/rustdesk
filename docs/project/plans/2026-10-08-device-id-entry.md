# 设备 ID 入口与本地验证

日期：2026-10-08。沿用 `feat/harmony-controller` 与 10 月 5 日的 ID/中继设计。用户确认尚无自建服务器，先完成代码和本地验证，真机验收后移。

## 目标与边界

首页提供可操作的设备 ID、IP 直连和强制中继入口。ID 负责寻址，服务公钥验证协调服务，设备公钥验证被控端；首次使用仍需导入或核对公开设备资料。连接成功后仍须 Windows 现场批准，默认控制，可选仅查看。

采用已保存 profile 的 ID 查询与选择，复用现有编辑、导入、持久化和会话生命周期。未知 ID 引导添加或导入，不借用其他设备的公钥。相同 ID 在不同服务上可能表示不同设备，必须选择具体资料。保留每台设备显式绑定的服务配置，不引入可静默替换已保存信任的全局覆盖。

不采用仅输入 ID 即信任网络返回密钥的方案，也不重复实现已有 rendezvous 协议。用户未部署服务前，不使用公共服务默认值，不开放公网端口或修改防火墙。

## 完成标准

用户能从主页明确选择连接方式、输入 ID、选定其可信配置并调用现有远控会话；配置缺失或身份不符必须明确失败。自动化证明 ID 选择不会串用身份，真实服务验证结果可复现且不与公网/真机验收混淆。
