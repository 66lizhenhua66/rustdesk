# 桌面分辨率切换与恢复验证记录

日期：2026-10-09。基线：`ce1b8682e`。用户已确认两种分辨率策略并授权补齐切换、重建、回退与恢复。见 [实施计划](../plans/2026-10-09-desktop-resolution.md)。本记录区分代码、自动化与构建证据和未完成的真机验收。

## 使用方式与已实现范围

普通会话在浮球「画质 / FPS」中独立选择分辨率策略、分辨率、压缩清晰度及 FPS，点击「应用设置」后等待实际回执。面板分别显示当前传输、当前 Windows 和本次连接前的尺寸；错误回执显示原因及实际保留的设置。

| 设置 | 行为 |
| --- | --- |
| 保持 Windows 桌面（默认） | 仅缩放传输画面，可跟随源画面或选择 1280×720 / 1920×1080 / 2560×1440 上限，保留比例且不放大源图 |
| 跟随源画面 | 每轴不超过 4096，总像素不超过 8,294,400；常规横/竖屏 4K 可原尺寸传输，更大源图等比缩小 |
| 同步调整 Windows 桌面 | 仅列出主屏驱动支持且保留刷新率、色深、方向与显示标记的尺寸；需普通现场批准会话已开启控制，本机输入能力仍允许 |
| 恢复连接前分辨率 | `(0,0)` 在同步策略下恢复本次会话记录的原始模式，不代表显示面板原生分辨率 |
| 压缩清晰度 | 省流 / 均衡 / 清晰，与分辨率独立，沿用编码质量参数 1.0 / 1.5 / 2.0 |
| FPS 上限 | 10 / 15 / 30，静止画面不重复编码，目标上限不等于实际帧率保证 |

新连接始终采用保持策略，默认 1080p、均衡、15 FPS。保存下次默认值时不会保存自动同步 Windows 桌面的行为。由同步切回保持时先恢复连接前模式，再按选定上限编码。没有新增 DPI、刷新率设置，也没有写入持久显示模式。

## 切换与恢复流程

1. 控制端串行提交单项设置请求，清除旧输入队列并先发送 `release_all`；等待期间拒绝新输入和启用控制，允许关闭控制并继续发送内部心跳。
2. Windows 保存本轮输入状态并内部撤销旧令牌，停止旧视频 worker，关闭队列并等待线程退出，确保释放旧采集/编码资源。
3. 需要改桌面时先校验模式、检查外部显示变化并原子写入恢复日志，再以 `CDS_TEST` 验证，使用临时 `ChangeDisplaySettingsExW` 切换。
4. 按实际桌面重建 GDI 采集与 VP8 编码器，取得尺寸匹配的首关键帧；按原控制状态重新授予新令牌，先发输入状态，再发设置确认和新首帧。旧令牌输入不会在新几何下执行。
5. 可恢复失败恢复上一桌面及视频设置，返回明确错误和可继续显示的首帧；恢复或输入释放失败则关闭会话。v2 初始及运行期设置等待上限为 20 秒，旧 v1 仍为 5 秒。
6. 正常断开/退出尝试恢复本次连接前模式。进程异常退出后的日志在下次显式启动安全被控服务时检查恢复；**没有独立看守进程，不会在崩溃瞬间自动恢复**。

恢复日志在应用配置文件旁，路径通过 `Config::file().with_extension("display-recovery.json")` 得到，保存所有者、原始状态、前一模式和申请模式。会话中保存完整原始 `DEVMODE`，日志保存恢复所需的设备、拓扑及模式字段。无待恢复日志时，启动钩子不会调用显示模式 API。

当前模式或显示拓扑与本会话预期不一致时，保持本机设置并停止同步修改。活动会话结束会清理自己已失效的记录；崩溃后发现外部变化则保留未解决记录，同步能力不可用。其他恢复失败会使服务启动明确失败。恢复记录不会覆盖无法确认归属的模式。

同一进程只允许一个 v2 会话持有显示修改权，包括该会话暂处于保持策略时；其他会话可保持桌面查看，但回执明确同步不可用。当前实现针对单主屏，不提供多屏或跨进程显示锁。

## 协议与兼容性

在 `libs/base` 的既有视频设置消息后追加 v2 分辨率字段、实际桌面、原始尺寸、支持列表、错误码及同步能力。使用既有 C ABI JSON 接口，不改变函数签名；`hbb_common` 子模块未改动。

初次登录的三个分辨率字段必须完整配对，仅允许保持策略；运行期不能跨设置协议版本。回执校验版本、序号、参数、尺寸与支持列表边界；失败回执只能报告先前实际采用的设置，允许携带外部变化后的实际桌面尺寸。保留 fixed64 请求序号和原有短明文拒绝策略。无设置扩展、v1、可信只读与 feature-off 路径继续使用原有行为；不新增无人值守键鼠或显示修改权限。
