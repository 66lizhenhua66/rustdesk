# 通过设备 ID 连接

设备 ID 是自建服务中的寻址标识。控制端仍核对被控设备的公开身份，Windows 每次普通连接仍需现场批准。首页默认进入控制模式，也可选择仅查看。

## 准备自建服务

准备 hbbs（ID/协调服务）和 hbbr（中继服务）的地址，以及 hbbs 公开验证公钥。不要填写私钥。服务需要支持当前入口要求的签名加密 TCP 信令；版本和可用性以实际兼容性验证为准。程序没有公共服务默认值。

Windows 使用已有正式整包，显式启用 ID 注册、视频和键鼠能力：

```powershell
& ./scripts/start-windows-host.ps1 -Video -Input `
  -Rendezvous 'hbbs.example:21116' `
  -ServerKey '<hbbs 公开验证公钥>' `
  -Relay 'hbbr.example:21117' `
  -Allow '<控制端实际来源 IP>'
```

`-Allow` 接受最多 16 个具体 IP，不能填通配符。中继场景也填写控制端来源，不能用 hbbr 地址代替；来源由已认证的 hbbs 提供。动态移动网络来源变化后，当前版本需要在 Windows 更新配置并重启。脚本不修改防火墙。

ID 注册成功后生成 `apps/harmony-controller/artifacts/official-current-id-profile.json`。文件只包含公开的连接和信任资料，不包含私钥或登录密码。IP 配置仍输出为 `official-current-profile.json`，两者可同时导入。注册失败时先检查日志，不使用遗留配置文件的存在来判断在线。

## 控制端首次添加

1. Windows 侧核对 ID 和公开身份，将本次导出的 ID JSON 复制到控制端。
2. 鸿蒙工作台选择「导入公开配置」，预览并核对设备 ID、设备公钥指纹、服务地址、公钥和中继后保存。也可以选择「设备 ID」并手动添加这些资料。
3. 首页选择「设备 ID」，输入目标 ID。相同 ID 若存在多份服务配置，选择对应服务下的设备资料。
4. 选择「控制」或「仅查看」，点击连接，在 Windows 工作台批准本次连接。

未保存的 ID 会引导添加或导入，不能借用另一台设备的身份资料发起连接。服务公钥与设备公钥用途不同，不能相互替代。重新导入相同本地标识不会覆盖已有信任资料；换服务或换设备密钥时需要重新核对。

## 三种连接方式

| 入口 | 行为 | 需要的资料 |
| --- | --- | --- |
| 设备 ID | 服务协调 TCP 直连，建连失败后尝试指定中继 | ID、设备公开身份、hbbs 地址/公钥、hbbr 地址 |
| IP 直连 | 直接连接设备地址 | IP/端口、设备公开身份 |
| 安全中继 | 强制使用配置的中继 | 与设备 ID 相同，保存方式选择强制中继 |

连接方式保存在每份设备资料中；首页筛选对应方式的资料，不临时改写已保存设备。需要将某个 ID 改为强制中继时，在无活动会话时编辑该设备的连接方式。控制端显示的实际路径来自核心事件，可区分 IP 直连、ID 协调直连和中继。

目标身份错误直接终止，不通过降级或换服务绕过。当前只实现 TCP 协调，不含 UDP/WebRTC；信令断开后需要重启被控入口。没有自建服务时可以完成代码构建和本地协议测试，不能据此宣称跨网络连接已可用。
